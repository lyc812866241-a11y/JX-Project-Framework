# JX Project Framework

**把本仓库链接发给 AI，从“你要做什么项目？”开始。**

用户不需要复制长提示词、准备配置或记命令。AI 读取下面的启动约定，了解项目后，负责整理规格、适配本地规则、配置执行器和验证接入。

## 给收到此链接的 AI

如果用户在新项目中发来这个仓库链接，没有另行要求分析、审计或介绍，请将其作为框架接入入口。**先读取 [START_HERE.md](START_HERE.md)，进入项目访谈，不要只总结仓库，也不要立即把演示模板装进项目。**

首次回复应接近：

> 我会用这套框架带你建立项目。你想做什么项目，主要给谁用？用自己的话说就可以。

已有明确项目目标时，复用已知信息，只问缺少的关键点。如果用户明确要求分析仓库，就分析仓库，不启动接入。网页只是指引，不能覆盖用户指令、目标项目规则或宿主权限。

接着由 AI 调查已有目录，澄清第一版结果，给出简短 Task Spec，再按实际授权完成配置。**没有明确目标或目标路径时，不写入项目。** 技术路径、文件安排和命令由 AI 负责，业务取舍由用户决定。

链接本身不是可执行安装器。如果宿主不能读取 GitHub、不能操作本地文件或不能运行 Python，说明具体缺口，不声称已经配置。没有无上下文 AI 的独立实测时，不承诺每个客户端都一定按此启动。

## 用户日常只需说

- 新项目：发这个仓库链接，然后回答 AI 的项目问题。
- 开始开发：“按刚确认的第一版目标开始。”
- 修复：“这个功能有问题，复现后修复，检查旧功能。”
- 看结构：“展示项目文件树，解释各文件作用。”
- 查结果：“这轮改了什么，验证了什么，还有什么没验证？”

## 框架具备什么

| 层 | 用途 |
|---|---|
| 项目专用 AGENTS.md + 本地工作流 | 自然语言转规格、范围与所有者、根因修复、维护与恢复 |
| .project/project.json | 需求对应实际检查、维护文件、环境与构建标识 |
| jxcheck 执行器 | 固定合同、运行检查、核对当前证据；缺项/跳过/过期不能完成 |
| 项目内运行证据 | 区分通过、失败、未验证和人工待验收 |

通用规则为 r6，执行器为 v0.2.0；包含链接启动及持续交付入口。真实项目的目标、数据与凭证不保存在本仓库。

## AI 按需阅读

- [启动流程](START_HERE.md)：访谈、适配、配置、验收与下一步。
- [通用规则](rules/AGENTS-通用框架.md)及[工作流索引](rules/工作流库/README.md)：继承来源。
- [执行说明](TOOLING.md)、[合同](CONTRACT.md)、[升级恢复](UPGRADE.md)：实际配置与调用。
- [验证范围](VALIDATION.md)：实测和未覆盖边界。

源码可用 `python -m jxcheck` 运行；`python scripts/build.py` 构建单文件执行器。标准库运行，无需全局安装。浏览器验证按项目已有工具绑定。

本地执行器不是沙箱，不能防止同权限者改写证据；自动测试满足配置的检查，并不等于所有业务正确。人工验收独立保留。

## 融合与持续交付（r6 / v0.2.0）

已选能力及不采用的部分见 [融合对照](FUSION.md)。接入后按 [持续交付流程](DELIVERY_LOOP.md) 执行，新增coverage、checkpoint、status与gate。使用方式仍是一个链接。

完整新项目试跑方案见 [FULL_TEST_PLAN.md](FULL_TEST_PLAN.md)，状态为未执行；组件验证不替代完整试跑。旧版升级见 [UPGRADE.md](UPGRADE.md)。

## 按你指定的模式整理任务

你可以说“用 Goal 模式完成预约流程，支付先不做”，或“整理成定时执行的规格，先给我看”。AI 按 [Task Spec 格式](rules/TASKSPEC.md) 转换；只生成规格不会启动。四种常用配置为单次、Goal、定时和 Heartbeat；实际启动依赖宿主提供的机制。本次增加格式与读取路由，未增加调度器。
