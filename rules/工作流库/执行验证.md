# 执行验证

类别：K12 的执行细则，由必备 W04/W02/W05 路由；不是每轮额外全量流程。版本：2026-09-10-v1；执行器 v0.2.0。

## 触发与输入

初始化/升级具体项目时绑定；产生可验收交付、修复回归、检查定义或源码变化时执行。输入：目标实际规则、已批准 Task Spec、读写范围、需求与重要不变量、运行条件、适配本领域的检查与人工项。

规则与检查器是两层：AI 负责按项目语境选择标准和维护资料，程序校验合同并采集执行证据。不能将程序结构检查等同于语义继承或业务正确性。

## 流程

1. 按 W04/W05 复用本地文件和维护者；在 `.project/project.json` 绑定实际路径、需求 ID、检查 ID、可观察期望、必需性、所有者、步骤、证据、参数数组/cwd 和非敏感环境/构建标识。文件名按领域适配。
2. 准备项目专用 manifest，init/upgrade 先预览；按已有授权应用。冲突保留用户内容，不复制旧个人权限。锁定规则/执行器来源和摘要，运行 doctor，语义继承另做场景审阅。CLI 只做绑定安装，不替代完整项目初始化或 Git 规则。
3. 当前 Task Spec 获批后，用 task 命令冻结检查合同、规格和写集基线。简单已批准工作不逐步骤再确认；首次变更合同、扩大范围或外部副作用按原边界处理。不能把 CLI 捕获命令当用户身份认证。
4. 修复先保存原缺陷复现或在隔离副本跑出失败；新增针对性回归，保留重要旧流程。JUnit 配置受保护测试名，测试意义/期望变化另审，不能静默删除或放宽。
5. verify 运行登记的命令或领域断言，采集结构化报告/截图。必需失败、跳过、零测试、错误、缺附件不能通过；源码/测试/配置/未跟踪文件变化后保守重跑。不支持报告格式明确待适配。
6. W05 同步受影响状态、地图、接口、环境和维护流程后，重新 verify、finish，避免同步文档后继续使用旧证据。范围外变化先解释并处理，不能直接扩大通配符掩盖。
7. finish 返回 ready/pending_manual/blocked/stale。人工项缺可信确认来源则保留待人工验收；ready 只代表配置标准满足。结果附证据路径、实际覆盖、变化与恢复点。

## 维护与边界

执行器/规则升级先看差异、保存旧包与文件恢复点；重审继承与正常/负例。项目接入登记区分已绑定、本地实测、远程门禁实测。源升级不自动传播旧项目。

本地同权限可绕过；没有宿主 Hook、身份认证或远程保护时明确写明。密钥不放参数/报告；秘密环境与外部服务变化需项目补充验证，不由哈希推断。无软件领域采用文件/状态/来源检查及人工项，不强制 .env 或软件测试。

实际命令和字段：[执行包说明](../../README.md)、[合同](../../CONTRACT.md)、[恢复](../../UPGRADE.md)。在专用项目落地时转换为项目可达的本地路径，不依赖 JX 的个人绝对路径。

## 最低验收

正常检查可完成；原缺陷回归能失败；检查定义改变/必需跳过/零测试/证据替换/检查后改源码不能完成；无人工凭证不冒充通过。至少一条真实项目入口验证后才登记本地实测。包内隔离样例不是所有业务项目接入证明。
