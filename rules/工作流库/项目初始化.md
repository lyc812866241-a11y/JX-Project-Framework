# 项目初始化

类别：基础必选，ID：W04。执行标识：`PROJECT_INITIALIZATION_V1`。

## 触发与口令

用户明确要求初始化或接管一个具体项目时触发。仅讨论、编写本工作流或展示文件树，不执行初始化。此流程是通用框架生成流程的项目级操作入口，不递归调用自己。

> 初始化项目【绝对路径】，目标是【要实现的结果】。先读取现有规则、文件和 Git 状态，区分已有结构与拟建结构；按 JX 通用框架建立最小项目规则、文件职责与依赖地图、共享接口和任务边界。已有项目只补缺，不重建。实现细节你调查后提出，关键业务取舍再问我。完成后展示实际文件树、每个业务文件的职责、依赖依据、待确认项和下一步。

未知项目路径必须先确定；未知技术栈先调查或给出方案，不随意创建业务骨架。用户使用该口令授权框架规定的本地初始化，不自动授权付费、发布、外部通信或批量创建任务。

## 输入

- 项目根目录、用户目标、当前阶段与约束。
- 已有 AGENTS.md、需求、配置、真实文件清单、Git/worktree 状态；不存在则如实记录。
- 通用框架及工作流索引中的全部必选规则。必选表示继承触发规则，不表示初始化时运行部署等不相关流程。

## 执行步骤

1. 按自然语言转换机制形成五项 Task Spec：目标、上下文、范围、约束、验收。已有任务记录则复用；区分用户决定和 AI 建议。
2. 检查现有目录、上级仓库及工作树。空项目从需求确定最小模块；已有项目从真实结构出发，不为符合模板批量移动、覆盖或重命名文件。
3. 执行系统建模：需求/结果 → 模块职责 → 输入输出 → 状态所有者 → 验证入口。先明确模块与接口，再映射文件；不要求提前设计所有未来文件。
4. 展示两张明确分开的清单：实际文件树（已存在）、拟建最小结构（计划）。对每个纳入范围的业务/规则文件说明作用和必要性；生成物、依赖包、二进制资产按类别说明，不为它们编造代码职责。
5. 形成项目地图：优先更新已有架构/索引；若没有，使用根目录 `项目文件与依赖地图.md`。包括相对路径、职责、输入输出、直接依赖、共享合同、写入所有者、证据与未知。文件树展示位置，依赖图展示关系，两者不混为一谈。
6. 共享接口应有唯一合同或定义位置。定位实际类型/Schema/路由定义，说明消费者、兼容约束和维护者；未实现接口标计划。维护者可先按角色指定，未分配的具体任务负责人标待分配。
7. 在授权范围内生成/补齐项目专用 AGENTS.md，继承核心清单和必选工作流，明确项目地图入口和刷新触发。只创建当前需要的文件；业务代码或脚手架必须在本次目标和适用授权内，不安装未知依赖。
   - 执行 [项目维护 W05](项目维护.md) 第一节：绑定当前任务/状态、地图、历史/证据、维护流程的实际路径或章节及所有者；保存读取/更新触发和验证方式。环境与接口按实际场景绑定说明、无密钥示例及验证入口，无场景记录重新启用条件。缺少必需绑定不得宣布初始化完成。
8. 按通用框架 Git 初始化规则执行：已有仓库/worktree 沿用；无仓库才在确定的项目根目录初始化，补充适用 .gitignore。不得嵌套初始化、自动提交或推送。规则维护和只读地图展示不触发此步骤。
9. 校验落地文件、引用与地图证据；完成核心继承映射。输出下一任务建议及其目标、必读上下文、允许修改范围、共享文件所有者、依赖和验收。创建执行任务另按用户授权及工具规则处理。
   - 对目标本地条款执行 W05 第五节正常与反例审阅；核对 K01—K12、W01—W05，记录源版本/哈希、目标落点与文档/运行验证状态。不能只列出 ID，不能把源库链接代替本地维护能力。

## 地图输出合同

```text
项目根目录、观察日期、扫描范围、折叠/排除项、Git 基线（若存在）
实际文件树：每个展示文件一句职责，未知写“待核对”
拟建结构：单独展示，绝不标成已存在
文件职责表：路径 | 作用 | 输入输出 | 直接依赖 | 依据 | 状态
共享合同表：合同/符号 | 定义文件 | 消费者 | 写入所有者 | 兼容边界
一条代表性流程：入口 → 处理 → 数据/外部接口 → 结果
任务边界：任务 | 目标 | 必读文件 | 可写文件/符号 | 只读共享文件 | 依赖 | 验收
未知、冲突及下一步
维护登记：记录角色 | 实际路径/章节 | 读取/更新触发 | 所有者 | 更新动作 | 验证/证据 | 适用条件
```

## 验收与反例

- 新项目：最小结构服务于当前需求，实际与拟建分开；没有提前铺满未来目录。
- 已有项目：不覆盖用户内容、不建嵌套仓库；原文件改动保留，地图反映当前文件。
- 依赖有 import、调用、配置引用或文档链接依据；动态加载无法静态确认时标待运行核验。无依据不画为确定关系。
- 两任务涉及同一接口：合同维护者、消费者与协调顺序明确；不同工作树不免除接口协调。
- 找不到目录、职责未读清、核心条款缺失、引用失效：标未完成项，不声称初始化全部成功。
- 重复初始化仅补差异，不再创建同名规格、地图或仓库。

## 维护

文件新增/删除/重命名、职责或接口/调用关系变化时，同次变更更新地图；分任务前重新核对相关范围，不能拿旧地图直接授权写入。地图是导航，任务范围仍需落到具体功能、符号和接口合同。

初始化绑定以后，按目标本地 W05 流程维护，不在每次变化时重新初始化。升级也先复用已有记录与绑定；更新此初始化流程本身时，核对通用源、工作流索引及继承场景。

核对 K01—K12、W01—W05，按 [执行验证](执行验证.md) 为实际项目准备配置和安装清单、预览差异、锁定版本、运行 doctor，再做语义适配审阅。CLI init 只安装已准备的绑定，不自动特异化全部业务或初始化 Git；第 8 步 Git 规则仍由项目流程负责。只有绑定和本地正反例实际运行都有证据才记录本地实测；不得自动迁移旧项目。
