# 工作流库

通用框架读取此索引，先纳入基础必选工作流，再按项目需要选择可选工作流。

## 基础必选

初始化时实际读取以下五个文件，将适配后的规则及触发条件写入项目专用框架。必选代表必须纳入规则，不代表每次任务都执行全部流程。未触发的流程不创建配套空文件。

| 工作流 | 触发条件 |
|---|---|
| [项目初始化](项目初始化.md)（W04） | 用户明确初始化/接管具体项目；建立最小结构与职责/依赖地图，已有项目只补缺 |
| [系统建模](系统建模.md) | 项目初始化，或目标、结构、流程、约束发生变化 |
| [验证收尾](验证收尾.md) | 每次产生可验收交付物后 |
| [发布回滚](发布回滚.md) | 发布、部署、数据迁移或恢复操作；无发布场景时注明不适用 |
| [项目维护](项目维护.md)（W05） | 初始化时绑定记录与维护责任；状态、结构、接口、配置或规则变化及交接时增量维护并验证 |

## 按需选用

用户快捷口令：初始化项目见 [项目初始化](项目初始化.md)；“展示项目文件树与依赖，解释每个文件的作用”见 [系统建模](系统建模.md) 的只读展示入口。它们是自然语言约定，不是客户端内置斜杠命令。

只有当前项目有明确需求时才读取并纳入。例如 UI 设计仅在涉及界面设计时选用。
目前尚无可选工作流文件；UI 设计只是分类示例，不代表已有流程。

## 新增方式

一个工作流一个 Markdown 文件，写清用途与触发条件、必要输入、步骤、产出与填写要求、验证方式，并在此索引登记类别和链接。保留方法的来源与验证状态；不预建空文件。

## 执行验证路由（r5）

[执行验证](执行验证.md) 是 K12 的条件执行细则，纳入 W04/W02/W05，沿用五项必选结构。项目初始化/升级绑定，交付和修复时调用；实际工具见 [执行包](../../README.md)。
