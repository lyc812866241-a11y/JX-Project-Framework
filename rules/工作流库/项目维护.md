# 项目维护

类别：基础必选 W05；核心对应 K11。版本：2026-09-10-v1。执行标识：`PROJECT_MAINTENANCE_V1`。

## 目的与边界

使任何采用本框架的项目都能回答：事实放哪里、何时读取、变化后更新什么、谁来维护、怎样核对、如何恢复，以及维护规则本身怎样更新。软件、学习、研究项目继承相同能力，文件名和验证方法按领域适配。

初始化负责绑定，系统建模负责结构事实，验证收尾调用本流程确认同步，发布/回滚完成后更新实际基线；本流程不循环调用初始化或再次启动收尾。只读审阅不写文件，纯解释不强制建记录。用户已授权的实施包含范围内必要资料维护；超范围或外部操作依原门禁处理。

## 一、初始化或升级：绑定维护对象

先调查已有资料。AGENTS.md 保存触发和路由；较长的本地维护流程可写入现有 WORKFLOWS 或独立文件，登记表复用 INDEX 或本地维护流程。不能仅引用通用库而不写本项目实际路径、责任与步骤。

维护登记表字段：`记录角色 | 实际路径/章节 | 唯一职责 | 何时读取 | 何时更新 | 写入所有者 | 更新动作 | 验证方式 | 证据位置 | 适用条件`。

| 必须检查的记录角色 | 最小内容 | 条件与合并方式 |
|---|---|---|
| 入口和维护流程 | 路由、规则、登记表、更新步骤及版本 | 必须绑定；小项目可直接内嵌 AGENTS.md |
| 当前任务/项目状态 | 目标、范围、阶段、已完成/未完成、阻塞、下一步、依据与更新时间 | 必须绑定；单任务项目可合并；跨任务状态引用细节而不复制流水账 |
| 结构地图 | 实际文件职责、输入输出、依赖依据、共享接口及维护者 | 必须绑定；可使用已有架构或索引章节；拟建结构分开 |
| 历史/决策/恢复证据 | 原计划、变更原因、已确认决策、验证结果与恢复点 | 必须绑定；可用任务文件历史区，不强制另建日志库 |
| 环境与外部接口 | 运行条件、配置变量、加载方式、服务/接口合同、示例与验证方法 | 涉及程序、工具服务或外部输入时启用对应部分；当前无场景说明原因及再次检查触发，不生成空 .env |

所有者写明确的项目角色；单人项目可写当前执行者，协作项目指定汇总者与共享文件唯一维护者。必需角色无路径或无所有者应判未完成。表格中的实际路径不得保留模板占位符，暂无证据的业务事实可以标待核验。

## 二、每轮按变化联动维护

普通执行按本节增量维护；任务结束、用户要求归档/换窗口/交接时，另执行第六节完整核账；新窗口接任执行第六节接任核验。完整核账不是每轮重复全量读取。

1. **读取基线**：读取当前任务、登记表和本次相关事实，核对实际文件及版本（有 Git 时检查目标工作区；没有 Git 时记录本次读取/改动依据）。只读检查定位差异，不修改无关内容。
2. **列出影响**：按下表选择命中行，列入同一任务的必要写集，区分原有用户改动和本轮改动；依赖及接口影响按内容查证，不能只看目录。
3. **更新唯一事实源**：先更新承载实际事实的源文件，再更新地图、索引、状态等引用者；写共享文件前重读并保留并发修改。跨任务写入由登记所有者完成，无权限时交接最小增量并记待同步。
4. **核对一致性**：逐项检查相关路径/符号仍存在、状态/统计/下一步一致、接口消费者及配置示例匹配、没有把计划写成完成。比较证据与当前摘要；不以时间新旧代替真实性判断。
5. **保存恢复点**：重要进展、阻塞、暂停/交接或纠正后保存最小状态。当前摘要更新为有效结论，旧内容进入历史区或清楚标为已被替代，保留原计划、来源与变更原因；未知事实保持未知。
6. **向用户交付变化**：采用第三节合同，并对必需维护缺项给出责任与下一步。全量日志归档不是每轮必需，也不创建定时任务。

| 变化类型 | 必须核对/同步的对象 | 最低验证 |
|---|---|---|
| 目标、范围、状态、下一步改变 | 当前任务、项目状态、直接依赖该状态的计划/交接 | 当前有效结论一致；历史原计划保留；统计重新按规则核对 |
| 文件增删移动、职责或依赖改变 | 文件地图、读取索引、引用者、任务写集 | 旧路径引用清理或注明历史；实际树与图一致；未知依赖披露 |
| 共享接口/字段/输入输出改变 | 唯一合同、消费者、验证入口、地图及环境说明的相关部分 | 兼容与迁移影响明确，消费者对应修改/协调，约定验证有证据 |
| API、服务、环境变量或加载方式改变 | 环境说明、无密钥示例、配置读取/检查、相关接口和适用忽略规则 | 名称与程序消费一致；缺失配置行为、环境差异和连通/业务验证分别说明 |
| 规则、维护步骤或模板改变 | 本地 AGENTS 入口、登记表、受影响工作流/模板、继承记录 | 触发能到达有效本地步骤；版本和适配一致；正常/反例场景复查 |
| 验证失败、回滚、暂停或移交 | 当前状态、真实基线、失败证据、恢复点、受影响地图/环境 | 不继续报告旧的成功状态；下一执行者能定位未完成动作 |

## 三、每次文件迭代的交付合同

```text
本轮文件变化：新增/修改/删除/移动的路径，各自原因与结果
结构影响：职责/依赖/共享接口如何变化；未变化也明确说明
关联资料：已同步哪些；哪些待同步、原因及维护者
验证：通过/未通过/未验证，证据和实际检查范围
恢复：未完成项、下一步、必要的版本或恢复位置
```

结构变化时展示受影响的文件树或关系图，并说明箭头含义；普通内容修改无需重画全项目。文件多时在任务记录保存完整变化清单，回复链接并总结关键影响。未修改文件就如实写明，不虚构 diff。必需维护未完成时，不把业务实现完成等同于整轮完成。

## 四、环境与配置的条件维护

- 区分业务程序配置、Codex/其他工具配置、部署平台配置；分别定位实际消费者和作用域，不把 AGENTS.md 当配置加载器，不顺带修改用户全局配置。
- 环境说明至少记录：变量名、用途、消费者、是否必需、非敏感默认值/格式、配置来源、加载方式及优先级、适用环境、缺失时行为、验证方式、维护者。加载与优先级从实际实现查证，不假定 .env 自动加载。
- 若项目使用环境变量示例，优先复用 `.env.example` 或等价机制，只放名称、空值或明确假值。真实凭证不写入规则、地图、历史、示例、回复或日志；按项目批准的凭证存储与注入方式处理，验证只报告存在/缺失或脱敏结果。
- 本地敏感文件采用适用的 Git 忽略规则；如使用 Git，核对忽略是否生效并检查是否已被跟踪，已跟踪不能声称加 ignore 后已安全处理。发现凭证问题只记录文件位置和处置需求，不显示值、不擅自重写历史。
- 校验分层：名称/格式/必需项 → 程序能否正确读取 → 已授权环境的服务连通 → 本次业务结果。未取得凭证、无网络或不允许外部请求时保留待验证，不为完成文档而购买、发消息、部署或调用付费接口。
- 非软件项目适配为资料来源、外部工具、输入格式和证据要求；没有这些场景时记条件不适用，新增外部服务/接口/运行程序时必须重新检查。本流程不要求所有项目创建 .env 或 config.toml。

## 五、维护流程自身的升级与继承验收

源框架新增或改动维护规则 → 更新核心/工作流登记 → 同步初始化和收尾入口 → 保存原因/版本/受影响文件 → 检查引用与下列场景。目标项目升级另需在其授权范围读取源差异、绑定本地对象并记录源 SHA-256、目标版本与映射结果；不自动传播到所有项目。

K11/W05 映射还须包含第六节完整核账与接任核验的本地落点、所有者、核账记录及当前恢复点位置。可合并现有任务/交接文件；不能只留通用库链接，不能仅凭存在 checkpoint 判完整交接。

每个目标必须保存 `场景 | 目标实际路径/章节 | 预期动作 | 审阅证据 | 文档结果 | 运行验证状态`。先绑定再审阅；不能只复制本表并填“通过”。

| 场景 | 应有结果/拒绝条件 |
|---|---|
| 一项任务完成，另有未完成项 | 当前状态、引用它的计划和下一步同步；原计划留历史；只追加第二个相互冲突的“最新状态”不通过 |
| 文件移动且被多处引用 | 地图/索引/使用方更新，报告旧→新及影响；链接能打开但指错对象仍不通过 |
| 软件新增一个 API | 绑定环境说明、变量消费与示例、接口/消费者、维护者和验证；只有“注意密钥”不通过 |
| 学习/研究新增外部输入 | 绑定资料/工具来源、格式与证据条件；无软件场景可不建 .env，但不能删掉条件触发 |
| 本地维护流程换路径或升级 | 入口、登记表、调用工作流与版本映射同步；只保留旧源库链接不通过 |
| 移除 K11/W05、必需所有者或实际路径 | 继承缺项，判未完成；标题和 ID 存在仍需语义审核 |
| 只读展示、两任务共享记录、重复初始化 | 分别保持只读、遵守单一写入所有者、复用现有绑定不重复创建事实源 |

验证等级必须明确：链接/字段检查证明结构存在，条款场景审阅证明设计有对应动作，真实任务证据才证明该次运行执行过。任何一层都不代表未来必然不遗漏。

来源：2026-09-10 用户要求通用框架具备并可向所有专用项目继承维护能力；复用现有 Task Spec、系统建模、验证收尾、归档恢复及继承合同。方案采用独立流程加根入口，避免向根规则堆叠业务细节。

## r5 检查合同与证据维护

将 [执行验证](执行验证.md) 的项目配置、执行器/规则锁、检查定义、任务基线和证据纳入维护绑定。源码/测试/非敏感配置/未跟踪文件变化使证据失效；资料同步后重验。检查与预期变化列差异，新任务修订保留旧记录。升级先预览并保留恢复点，冲突不覆盖，接入状态逐项目登记。语义继承与运行验证分开，不能以 doctor 字段通过代替业务判断。

## r6 状态恢复

按 [持续交付流程](../../DELIVERY_LOOP.md) 使用checkpoint/status保存与核对恢复点；业务状态及地图仍在绑定事实源，变化后重验，不把.artifacts中的进度记录当业务事实。


## 六、交接前完整核账与接任核验

执行标识：HANDOFF_RECONCILIATION_V1。此节是完整核账的唯一规范，属于K11/W05；由项目当前执行者归档，接任者核验，共享记录遵守原所有者边界。任务中增量维护，任务结束或用户要求归档、换窗口、交接时执行完整核账；纯解释不因此创建档案。用户要求暂停时先保存可得恢复点，不能以核账为由继续业务执行。未预期中断时不假称已经核账，恢复后补查。

### 旧窗口核账

1. 确定本次任务及可访问记录范围：当前对话、可读取历史/工具结果、任务文件和证据。记录起止或可定位的任务/消息/阶段标识、核账时点、不可访问部分。摘要只能作为摘要来源，不能宣称等同原始完整对话；不为核账读取无关私密任务，也不批量复制含密钥或敏感数据的原始聊天。
2. 顺着实际记录提取影响后续工作的事项：原始及最终需求、范围变化、决定和理由、用户纠正、实现和结构变化、测试结果与缺口、取消/搁置、未完成承诺、阻塞及下一步。对照原计划与后续改动，不只整理最后一条消息；建议、批准、计划、执行结果和用户自报分别保留证据层级。
3. 把事项归入既有权威文件：需求/范围到当前Task Spec，选择与理由到决策位置，实际成果到状态/地图/接口，验证到证据记录，纠正到反馈及必要规则，取消和遗留到历史/待办，恢复到当前摘要。先更新事实源，再更新引用者；保留原计划与替代原因。复用现有记录，不把整段对话写进AGENTS，不建立竞争的第二套事实源。
4. 在现有交接或任务历史区保存紧凑核账索引：`事项ID/来源依据 → 重要事项 → 权威文件及章节 → 已核对 / 待同步 / 不需保存及原因`。已核对必须实际打开目标内容，确认语义和当前状态吻合；只存在路径、章节为空、内容指向旧决定，都不能算已核对。重复事项可以合并，但来源与最终有效结论可追溯。
5. 做双向核对：记录中的重要事项是否都有落点；当前文件是否还保留被取消或替代的错误有效状态。未同步项登记原因、影响、所有者与下一步；无法访问的历史单列覆盖缺口。不能因行数齐全、无待同步行就证明未漏识别。
6. 保存唯一明确的当前恢复点：当前目标与规格版本、阶段、实际已完成、未完成/阻塞、下一步、必读文件/证据、当前版本及覆盖缺口。旧恢复点标历史或被替代；不能不断追加多个相互竞争的“最新状态”。写前重读保留并发修改，状态冲突未解决时明确记录，不以较新时间自动覆盖。
7. 收尾区分“业务验收状态”和“交接核账状态”。可访问范围的重要事项已归位且无必需待同步项时，才能报告该范围核账完成；有缺口可带缺口交接，但不能称完整无遗漏。工程资料变更后按现有流程重验最终输入；checkpoint只是证据/进度辅助，不证明归档内容完整，不因保存恢复点强行标业务complete。

### 新窗口接任

1. 先读根AGENTS、本地维护路由、唯一当前恢复点和核账索引，再按任务读取权威文件。不要全量重放历史，也不要只相信旧窗口总结。
2. 核验目标、有效规格/授权、未完成承诺、取消项、待同步项及下一步。工程任务核对实际根目录、分支/工作树、未提交改动、运行/验证版本和当前证据；非工程任务按资料、日账及来源核对，不强行创建Git仓库。
3. 对照当前文件与旧摘要，发现冲突、缺失或过期证据则标待核验/过期；在授权内修正恢复判断并留下差异来源，不静默丢弃历史。接任记录保存核验范围、结果、遗留项及本轮下一步，复用同一交接记录。
4. 非阻塞缺口明确披露后可继续独立工作；影响目标、授权、关键事实或验收的缺口须先调查，仍无法解决再问用户。不要把可查信息全部退回用户，不为同一授权重复审批。压缩后按此恢复；无法读取压缩前记录时披露边界，不假造遗漏内容。

### 正常与反例审阅

| 输入情形 | 必须得到的核账/接任结果 |
|---|---|
| 用户取消支付，但规格仍要求开发 | 识别有效状态冲突，保留取消依据与原计划，更新当前范围后才算已核对 |
| 旧窗口承诺后续修通知，但待办没有 | 未完成承诺应有落点；待归档前不能报告核账完成 |
| 交接称测试通过，实际代码随后改变 | 核对当前证据，旧通过不能继承为本轮有效通过 |
| 只读取摘要，原始一段历史无法访问 | 声明可访问范围和覆盖缺口，不能声称原始整段已核账 |
| 文件路径存在但章节没有对应决定 | 待同步或待核验，存在性检查不能替代语义核对 |
| 文件中有两个不一致的最新状态 | 指定有证据的当前结论、保留历史；证据不足保持冲突待查 |
| 必需待同步项仍存在 | 可带缺口交接并列负责人/下一步，不能宣称完整交接 |

本流程需在项目初始化/升级时本地化，绑定核账记录、恢复点及所有者，并核对上述场景。文档语义审阅、链接/隔离安装检查与真实跨窗口接任实测分别记录；本流程和现有CLI不能自动发现全部对话遗漏，也不能保证任何新窗口必然遵守。
