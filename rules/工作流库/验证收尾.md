# 验证收尾

类别：基础必选。
用途与触发：每次产生可验收交付物后，检查是否解决目标并留下必要的继续工作信息。
必要输入：当前目标与验收要求、实际交付物、相关执行结果。

## 步骤

1. 对照验收要求检查实际结果，按影响范围检查必要的异常路径及已有功能。文档检查事实与引用；学习成果检查复述、应用或实际操作，不以自报理解代替证据。
2. 区分通过、未通过、未验证；记录最小充分证据。软件的启动成功或 HTTP 200 不能独自证明业务完成。
3. 核对实际改动与约定范围，修正受影响的规则、模型和说明，保留尚未解决的问题。
   - 对有状态或文件变化的任务，按 [项目维护 W05](项目维护.md) 及目标本地登记执行变化联动核对：事实源、当前摘要、地图、接口、环境说明和读取入口是否按影响同步。只读任务不自动修复；缺项标责任与恢复点。W05 不再次调用本收尾流程。
4. 简短报告完成内容、验证结果与未解决事项。需跨任务恢复时，更新已有任务或状态文件，写清下一步起点；不重复存放完整日志。
   - 有文件变更时按 W05 第三节报告增/改/删/移、原因与效果、结构/依赖/接口影响、资料同步状态、验证与下一步；无结构变化明确说明。必要时展示受影响文件树/关系图，不每轮全量重画。必需资料维护未完成，不宣称整轮完成。

## 产出与验证

优先写入已有任务记录；简单任务可直接交付简短结果，不强制增加验证、收尾两套文件。
需要持久记录时填写：目标达成情况、实际改动、证据、未验证项、剩余问题及下次起点；版本与恢复点按任务需要补充。
完成标准：结论与证据一致，必需验收未完成时不宣称全部完成；工程验证和用户业务验收分别说明。已讲解、自报理解、实际操作、验证有效也须区分。

## r5 执行入口

按 [执行验证](执行验证.md) 运行 verify 与 finish。先完成 W05 资料同步，再验证当前最终版本；缺证据、必需跳过、零测试、回归失败或版本过期不能完成。人工项保留待验收；ready 仅表示满足配置标准。记录实际调用与证据，未接入执行器应如实标未验证，不用文字 PASS 代替。
